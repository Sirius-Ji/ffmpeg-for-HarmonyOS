# v0.3.0 功能扩展技术调研

> 状态：方案评估，未写实现代码
> 目标版本：v0.3.0（未打 tag）
> 约束：保持 LGPL-2.1-or-later；不引入 GPL/nonfree 组件；不破坏现有水印与分辨率链路

## 0. 结论摘要

v0.3.0 不建议继续往 `WatermarkFilter` 里堆条件分支，而是把现有视频滤镜图升级成一个**可组合的 FilterGraphPlan**：

```text
视频：
buffer(source)
  -> trim/setpts          （时间段 + 倍速）
  -> crop                 （画面区域）
  -> scale                （输出分辨率）
  -> hue/colorlevels/colortemperature（色彩）
  -> overlay              （图片水印 / 画中画，可带 enable 时间段）
  -> subtitles（可选）     （libass）
  -> drawtext             （文字水印，最后叠加）
  -> format=nv12
  -> buffersink

音频：
abuffer
  -> atrim/asetpts        （时间段）
  -> atempo / asetrate    （变速、变调）
  -> afreqshift/aecho     （音色效果）
  -> volume               （现有音量增益）
  -> aformat
  -> abuffersink
```

关键原则：

- 先裁剪、再缩放、再叠加；文字水印放最后，避免被缩放或色彩处理影响。
- 视频和音频使用相同的时间裁剪、倍速参数，统一由计划层生成，避免 A/V 不同步。
- 所有滤镜必须由 `--enable-filter=` 明确启用；不能假设“FFmpeg 源码里有就自动编进去”。
- 不引入 Rubber Band（GPL）。字幕的 libass 作为独立里程碑评估，先 spike 再合入。

## 1. 现状与约束

当前 v0.2.2 的视频链路：

```text
主 buffer -> scale -> overlay（图片）或 drawtext（文字） -> format=nv12 -> buffersink
```

当前实现有几个必须先知道的事实：

1. 视频帧在进入滤镜前已经被 `ScaleToNv12` 缩放；如果直接加 `crop`，crop 会作用在已缩放画面上，不符合“先裁原图再缩放”的语义。
2. 现有 `WatermarkFilter` / `ImageOverlayFilter` 在取帧后会覆盖 `filtered->pts = nv->pts`，这会破坏 `setpts` / `trim` 的时间轴。
3. 音频目前是“解码 -> swr -> AAC 编码”，没有走 avfilter；`atempo`、`afreqshift` 等音频滤镜无法直接复用视频图。
4. 当前 FFmpeg 白名单只启用了 `drawtext,scale,overlay,format` 等少数滤镜，新增能力必须同步扩展 `build-ffmpeg.sh` 和发布检查白名单。
5. 现有 `libentry.so` 与 HAR/ZIP 的依赖门禁已经稳定，v0.3.0 不应破坏 `libffz`、16KB 对齐、NEEDED 闭包这些约束。

## 2. 总体滤镜链设计

### 2.1 视频顺序（当前实现 / 目标实现）

**当前实现（截至 2026-11-17，实际代码）：**

```text
C++ trim（源 PTS 跳过 + pts -= trimStart）
  -> buffer(time_base=1/1000)
  -> crop -> scale -> color
  -> overlay（enable 用压缩前/后的统一映射）
  -> subtitles
  -> drawtext
  -> format=nv12
  -> OH 硬编码器按固定 24fps 连续 PTS 输出
  -> mux 层按 1/speed 压缩视频包时间戳
```

实际链路里**没有视频 `setpts` 滤镜**，倍速由 mux 完成。为保证字幕/PiP 的用户时间语义等于输出时间，本轮修复在送 buffer 前把滤镜 PTS 除以 speed：

```text
filter_pts = trim_relative_ms / speed
```

因此 ASS 的 5–6 秒、PiP 的 `between(t,2,6)` 都按**输出时间轴**解释；mux 仍负责把编码器连续包压成最终时长。

**说明：** 修复前字幕/PiP 工作在压缩前时间轴，1.25x 下会整体提前（ASS 5–6s 出现在输出 4.0–4.8s）。修复方案即上面的 PTS 映射；任务边界测试和最终回归仍待 V03-13 完成。

**目标实现（保留为修复目标）：**

```text
trim/setpts -> crop -> scale -> color -> overlay -> subtitles -> drawtext -> format
```

理由：

- `trim`/`setpts` 先确定输出时间轴，后续 `overlay enable` 的 `t` 才是输出时间。
- `crop` 必须在 `scale` 前，否则只能裁缩放后的画面。
- `scale` 在 overlay 前，图片/画中画的坐标和字号基于目标分辨率，不会糊。
- 色彩调整在 overlay 前，避免把水印颜色一起改掉。
- `subtitles` 在 overlay 后，字幕盖在画中画/图片上。
- `drawtext` 最后，保证文字水印始终在最上层；它和字幕可以共存，但需要明确层级。

### 2.2 音频顺序

```text
atrim/asetpts -> asetrate（可选） -> atempo -> afreqshift/aecho（可选） -> volume -> aformat
```

`asetrate` 和 `atempo` 的顺序不能反：`asetrate` 改变采样率/音高，`atempo` 把时长拉回目标；两者组合的推导见 §3.8。

### 2.3 计划层，而不是字符串拼接层

建议新增加一个中间结构（名字暂定 `FilterGraphPlan`）：

```text
VideoPlan:
  trim: {start?, end?, duration?}
  crop: {w,h,x,y}
  scale: {w,h}
  color: {brightness, contrast, saturation, temperature}
  overlays: [{source, x,y, enable:{start,end}}]
  subtitles: {path, fontsdir?, style?}
  drawtext: {text, x,y, size, color, alpha, bold}
AudioPlan:
  trim, atempo, pitch, effects, volume
```

UI/NAPI 只提交“计划”，C++ 负责校验参数、排列滤镜、处理输入源和 EOS。这样不会出现一个 `format` 字符串越来越长、每加一个功能就复制一份 filter graph 的情况。

## 3. 各功能方案

### 3.1 视频时间段截取

**最优表达式：**

```text
[0:v]trim=start=12.500:end=28.000,setpts=PTS-STARTPTS[v]
[0:a]atrim=start=12.500:end=28.000,asetpts=PTS-STARTPTS[a]
```

说明：

- `trim`/`atrim` 以输入时间轴为准，支持 `start`、`end`、`duration`。
- 截取后必须 `setpts=PTS-STARTPTS` / `asetpts=PTS-STARTPTS`，否则输出会保留 12.5s 的起始 PTS，封装层会出现空白或负时间。
- 当前转码管线会重新编码，因此用滤镜截取比 `-ss` 输入级 seek 更可控；如果以后做“无重编码截取”，再单独设计 keyframe/stream copy 路径，不能和滤镜路径混在一起。

**风险：** 视频和音频必须使用同一组 start/end；对于可变帧率素材，`trim` 后仍要重新计算输出时间基准。

### 3.2 画面区域裁剪（crop）

**表达式：**

```text
crop=w=1280:h=720:x=(in_w-out_w)/2:y=(in_h-out_h)/2
```

指定区域：

```text
crop=w=960:h=540:x=120:y=80
```

说明：

- 推荐让调用方传 `w/h/x/y`，C++ 做边界检查；不要只接受表达式，避免命令注入和非法值。
- YUV420 要求偶数宽高；`crop` 后至少保证 `w/h` 为偶数，否则编码器可能拒绝。
- 先 crop 再 scale，符合“从原始画面取区域，再输出目标分辨率”。

### 3.3 色彩调节

**亮度 / 对比度 / 饱和度（LGPL 方案）：**

```text
hue=b=0.04:s=1.15
colorlevels=rimin=0.05:gimin=0.05:bimin=0.05:rimax=0.95:gimax=0.95:bimax=0.95
```

不要使用 `eq`：FFmpeg configure 里 `eq_filter_deps="gpl"`，在 LGPL-only 构建中会被直接禁用。`hue` 负责亮度和饱和度，`colorlevels` 通过输入黑白点调整对比度。

**色温：**

```text
colortemperature=temperature=4500:mix=1:pl=0.25
```

或使用 `colorbalance` 做更细的阴影/中间调/高光偏移：

```text
colorbalance=rs=0.05:gs=0.0:bs=-0.05:rm=0.03:bm=-0.03
```

说明：

- `hue` 的 `b` 建议 UI 映射到 `-0.2..0.2`，`s` 映射到 `0.8..1.2` 或更窄，避免过曝/死黑。
- `colorlevels` 只用于对比度，输入黑白点不要超出 0..1；亮度和色温不要重复补偿。
- `colortemperature` 的 `temperature` 范围是 1000–40000K，`mix` 控制混合，`pl` 控制保持亮度。
- 色温和亮度/对比度不要重复做“亮度补偿”；建议 UI 只暴露一个亮度滑杆，色温只改白平衡。
- 滤镜应在 scale 后、overlay 前；这样水印不跟着色温变化。

### 3.4 字幕（SRT / ASS）

**方案：libass + FFmpeg `subtitles` / `ass` 滤镜。**

ASS：

```text
ass=filename=/data/.../sub.ass:fontsdir=/data/.../fonts
```

SRT：

```text
subtitles=filename=/data/.../sub.srt:fontsdir=/data/.../fonts:force_style='FontName=Source Han Sans CN,FontSize=24'
```

说明：

- FFmpeg 的 `subtitles` 过滤器依赖 libass，并且需要 libavformat/libavcodec 把 SRT 等字幕转换成 ASS 后再渲染；因此不仅要“编 libass”，还要启用字幕 demuxer/decoder（如 `srt`、`ass`、`webvtt`，具体名称以目标 FFmpeg 版本 configure 为准）。
- `fontsdir` 指向 App 沙箱里的字体目录，避免依赖系统字体。当前已经自带 `SourceHanSansCN-Regular.otf`，可以作为默认字体。
- `force_style` 里包含逗号和冒号，拼接时必须做转义；不要让用户直接传原始 filter 字符串。
- 字幕应放在 overlay 之后、drawtext 之前，保证画中画被字幕覆盖、文字水印仍在最上层。

**libass 交叉编译评估：**

- libass 本体：ISC，和 LGPL 兼容。
- 依赖：fribidi（LGPL-2.1-or-later）、freetype（FTL）、harfbuzz（MIT）、fontconfig（MIT 风格）、libunibreak（zlib 风格）；部分发行版还会带 iconv。
- 现有 freetype/harfbuzz 已经静态链接进 `libavfilter`，可以复用；需要新增 fribidi、fontconfig、libunibreak（按实际 libass 版本依赖裁剪）。
- 交叉编译工作量：高于 freetype/harfbuzz，低于“从零写字幕渲染器”。需要 pkg-config shim、静态库、关闭 asm/工具程序，并验证字体查找。
- **fontconfig 是最大不确定项**：libass 的系统字体查找通常走 fontconfig；如果 OHOS 上没有可用的 fontconfig，需要一起交叉编译，或者 patch 一个只使用 `fontsdir` 的 font provider。后者风险高，不建议第一版就做。
- 建议先做 2–3 天的 spike：只验证“libass 静态库能在 OHOS 上初始化 + 读取一个 ASS + 输出一帧”，通过后再接 FFmpeg `subtitles` 滤镜。

**LGPL 注意：** libass 是 ISC，不构成 copyleft；但 fribidi 是 LGPL，静态链接时需要提供可重链接的目标文件/源码与构建脚本，和现有 freetype/harfbuzz 的处理方式一致。发布前让合规检查覆盖这些新库。

### 3.5 视频倍速

**表达式：**

```text
setpts=PTS/1.25
```

`1.25` 是速度因子：`2.0` 表示 2 倍速，`0.5` 表示半速。

音视频同时：

```text
[0:v]setpts=PTS/1.25[v]
[0:a]atempo=1.25[a]
```

说明：

- `setpts` 只改时间戳，不改帧数；编码器的 `time_base`、输入帧 PTS 和封装时间戳必须按新时间轴处理，不能继续沿用当前“把 filtered->pts 覆盖成源 PTS”的做法。
- 音频 `atempo` 单实例范围是 0.5–2.0；超出范围要串联，例如 3 倍速：`atempo=2.0,atempo=1.5`。
- 倍速和 trim 同时存在时：先 trim 源时间，再 setpts/atempo，保证截取区间和速度定义一致。
- 建议 UI 的倍速范围先限制 0.5–2.0，超出范围作为后续能力，减少音视频同步风险。

### 3.6 画中画（PiP，时间段出现）

**表达式：**

```text
[0:v]scale=1280:720[base];
[1:v]scale=320:180[pip];
[base][pip]overlay=x=W-w-24:y=H-h-24:enable='between(t,5,15)':eof_action=repeat
```

说明：

- `1:v` 可以是第二个视频流，也可以是图片；图片作为一个静态 buffer，喂一帧后发 EOS。
- `enable='between(t,5,15)'` 使用 overlay 输入的时间轴（应位于 trim/setpts 之后），表示输出时间 5–15 秒出现。
- `x=W-w-24:y=H-h-24` 是右下角；坐标表达式以主输入为基准。
- `eof_action=repeat` 让静态图片在 enable 区间内保持；没有它，第二路 EOF 后可能出现黑块或提前消失。
- PiP 缩放应在 overlay 前完成，不要先叠再缩放，否则小窗会糊。

### 3.7 音频时间段截取

```text
atrim=start=12.500:end=28.000,asetpts=PTS-STARTPTS
```

与视频使用同一组 `start/end`。如果音视频分别从不同流读取，需要在计划层校验两路时长，避免尾部静音或截断。

### 3.8 音频变速不变调

**首选：`atempo`（FFmpeg 原生 WSOLA）。**

```text
atempo=1.25
```

范围超过 0.5–2.0 时串联。

**不要使用 Rubber Band：**

- FFmpeg 的 `rubberband` 滤镜依赖外部 Rubber Band 库，该库是 GPL-2.0-or-later；把它链接进 LGPL-only 产物会触发 GPL 义务。
- 如果未来单独提供 GPL 构建，可以作为可选项，但不能进入当前 LGPL 基座。
- 当前 FFmpeg n9.0 本地源码没有 `scaletempo2` 滤镜，`atempo` 是可用且协议安全的方案。WSOLA 的质量不如 Rubber Band 的某些模式，但对语音、常规音乐变速够用。

**评估结论：** 先用 atempo；如果后续确实需要更高音质，另开“GPL 可选构建”或寻找 ISC/MIT 的时间伸缩库，不在 v0.3.0 主包引入。

### 3.9 音频变调 / 变调 + 变速

**仅降调、不改时长：**

```text
asetrate=48000*0.9,aresample=48000,atempo=1.111111
```

**仅升调、不改时长：**

```text
asetrate=48000*1.2,aresample=48000,atempo=0.833333
```

**同时变调和变速：**

设 `p` 为 `asetrate` 的倍率，`s` 为目标速度倍率：

```text
asetrate=48000*p,aresample=48000,atempo=s/p
```

`atempo` 结果需要限制在 0.5–2.0；超出时拆成多级。`p` 不能过大，否则会引入明显共振/混叠，建议 UI 的变调范围先限制 ±4 个半音左右。

### 3.10 音频变声

**频率偏移（最接近“变声器”的简单方案）：**

```text
afreqshift=shift=120:order=8:level=1
```

`shift` 单位是 Hz，`order` 控制滤波器阶数，`level` 控制输出增益。

**回声/空间感：**

```text
aecho=0.8:0.9:40|60:0.4|0.3
```

**组合示例：**

```text
asetrate=48000*0.94,aresample=48000,atempo=1.06383,
afreqshift=shift=80:order=8:level=0.9,
aecho=0.8:0.9:40|60:0.3|0.2
```

说明：

- `afreqshift` 是频率搬移，不是“换声线”，适合做机器人/电话/卡通化的简单效果；真正的音色转换需要声码器/神经网络模型，不在 FFmpeg 原生滤镜能力内。
- `aecho`、`chorus` 属于效果器，不是变调；可以作为“空间感/厚度”参数。
- 变声参数变化大，必须做削波保护；建议在音频图末尾接 `alimiter` 或复用现有 PCM clip 逻辑，避免用户把 `level` 和增益叠到爆音。
- 当前音频管线是手动 PCM；要接这些滤镜，必须新增 audio filter graph，不能继续用纯 `swr_convert` 硬编码。

## 4. 外部库评估

| 库 | 用途 | License | 结论 |
|---|---|---|---|
| libass | ASS/SRT 字幕渲染 | ISC | 引入，但先 spike；需要 fribidi/fontconfig/freetype/harfbuzz |
| fribidi | 双向文本 | LGPL-2.1-or-later | 可引入；静态链接需履行 LGPL 重链接义务 |
| fontconfig | 字体查找 | MIT 风格 | 视 libass 方案引入；OHOS 上需要交叉编译/裁剪 |
| libunibreak | Unicode 断行 | zlib 风格 | 随 libass 依赖引入 |
| Rubber Band | 高质量时间伸缩 | GPL-2.0-or-later | 拒绝进入 LGPL 主包 |
| libsoxr | 重采样 | LGPL | 不是本次必需，暂不引入 |

### libass 的交叉编译流程（建议顺序）

1. 先编 fribidi（静态，关 tools/tests）。
2. 编 libunibreak（静态）。
3. 视实际 libass 版本编 fontconfig（静态，关文档/缓存工具），或先确认能否用 `fontsdir` + 内置 font provider 绕过。
4. 用现有 freetype/harfbuzz 的 pkg-config shim，编 libass（静态，关 asm/工具/测试）。
5. FFmpeg 增加 `--enable-libass --enable-libfribidi`，启用字幕 demuxer/decoder 与 `subtitles`/`ass` filter。
6. 在真机上只测“一个 ASS + 一个 SRT + 中文字体”，确认字体查找、大小、位置和换行。

**不要**把 libass 静态库直接丢进 `libavfilter` 而不更新 NEEDED/发布清单；这会重演 `libffz` 的问题。必须把新库加入 BUILD-INFO、SHA256SUMS、NEEDED 白名单和 SDK 的 `lib/<abi>`。

## 5. 与现有链路的整合

### 5.1 视频

当前实现是：

```text
ScaleToNv12 -> WatermarkFilter/ImageOverlayFilter
```

v0.3.0 需要改成：

```text
decoded AVFrame（源分辨率）
  -> buffer（源尺寸）
  -> trim/setpts -> crop -> scale -> color
  -> overlay（图片/画中画）
  -> subtitles
  -> drawtext
  -> format=nv12
  -> buffersink
  -> 编码器
```

注意：

- 删除编码前的 `ScaleToNv12` 预缩放；否则 crop 的输入不是源画面。
- 不要覆盖 `filtered->pts`；使用滤镜输出 PTS，编码器 timebase 随之调整。
- 图片水印保持“喂一帧 + EOS”；画中画视频保持第二路持续输入，结束时发 EOS。
- 文字水印的参数仍沿用 `watermark|text|position|size|color|fontPath|alpha|bold`，但由计划层解析，不再硬编码在 `ImageOverlayFilter::Init`。
- `subtitles` 失败时降级为“无字幕 + 明确日志”，不能静默丢整条转码。

### 5.2 音频

建议新增 `AudioFilterGraph`：

```text
abuffer
  -> atrim/asetpts
  -> asetrate（可选）
  -> atempo
  -> afreqshift/aecho（可选）
  -> volume
  -> aformat=sample_fmts=fltp:sample_rates=48000:channel_layouts=stereo
  -> abuffersink
```

音频和视频共用计划层的 `trim`、`speed` 参数；音频编码前不要再次改变时长。现有 `setVolume` 的 PCM clip 逻辑作为最后一道保护保留。

### 5.3 参数模型

建议把 v0.3.0 的 NAPI 从“位置参数 + 魔法字符串”升级为 JSON 配置（或独立结构体），至少包含：

```json
{
```

## 7. 版本纪律

- 本阶段只出调研文档和 Task 卡片，不写实现、不打 tag。
- 开发期间不创建 `v0.3.0-*` 中间 tag；需要标记进度时用任务看板状态或本地 commit，不用 tag。
- 只有 V03-01 ~ V03-13 全部闭环、`build/check-release.py` 全绿、双 ABI 产物和真机回归全部有证据，才创建唯一的 `v0.3.0` tag。
- 任何新外部库（libass/fribidi/fontconfig）进入产物前，必须更新 NOTICE、LICENSES、BUILD-INFO、SHA256SUMS 和 NEEDED 闭包门禁。
