
### 2. CMakeLists.txt（IMPORTED 方式）

`harmony/entry/src/main/cpp/CMakeLists.txt`，核心就这几行：

```cmake
set(FFMPEG_ROOT ${NATIVE_ROOT}/../../../libs/${OHOS_ARCH})

add_library(ff_avcodec SHARED IMPORTED)
set_target_properties(ff_avcodec PROPERTIES
    IMPORTED_LOCATION ${FFMPEG_ROOT}/libavcodec.so.63
    INTERFACE_INCLUDE_DIRECTORIES ${FFMPEG_ROOT}/include)

add_library(entry SHARED napi_init.cpp decoder.cpp)
target_link_libraries(entry PUBLIC
    libace_napi.z.so libhilog_ndk.z.so
    ff_avformat ff_avcodec ff_avutil ff_swresample)
target_link_options(entry PRIVATE "-Wl,-rpath-link,${FFMPEG_ROOT}")
```

`IMPORTED_LOCATION` 指向的是带版本号的文件名，这样 `DT_NEEDED` 写出来就是 `libavcodec.so.63`，和 `libs/arm64-v8a/` 下的文件名一致。

### 3. napi_init.cpp 暴露的三个函数

| 函数 | 做了什么 | HiLog 输出 |
| --- | --- | --- |
| `probe(path)` | avformat 打开 + 找流 + 建解码器 | `[open]` 两行 |
| `readPackets(path)` | 只解封装，数音频包/字节/PTS 范围 | `[read]` 一行 |
| `decodeToWav(path, wavPath)` | 整文件解码 → S16 WAV + FNV-1a 64 | `[decode]` 一行 |

`Index.ets` 已经把三个样本串起来依次调用。

## 预期 HiLog（tag = `FFM1`，domain = `0xFF01`）

点按钮之后，控制台应该出现这样的序列（数字来自桌面 ffprobe 实测，设备上应该一致）：

```
I FFM1 : [init] libentry.so loaded, ffmpeg=avformat/avcodec/avutil/swresample
I FFM1 : [open] path=/data/storage/el2/base/haps/entry/files/test.m4a
I FFM1 : [open] format=mov codec=aac rate=44100 ch=2 duration=5000ms bitrate=131488
I FFM1 : [read] packets=217 bytes=80513 pts=0..4985ms eof=1
I FFM1 : [decode] codec=aac frames=220500 bytes=882000 hash=9e253440599a9111 wav=...

I FFM1 : [open] path=/data/storage/el2/base/haps/entry/files/test.flac
I FFM1 : [open] format=flac codec=flac rate=48000 ch=2 duration=5000ms bitrate=289302
I FFM1 : [read] packets=235 bytes=172526 pts=0..5000ms eof=1
I FFM1 : [decode] codec=flac frames=240000 bytes=960000 hash=ade4c9dff2b87f33 wav=...

I FFM1 : [open] path=/data/storage/el2/base/haps/entry/files/test.opus
I FFM1 : [open] format=ogg codec=opus rate=48000 ch=2 duration=5006ms bitrate=120162
I FFM1 : [read] packets=251 bytes=74399 pts=0..5006ms eof=1
I FFM1 : [decode] codec=opus frames=240000 bytes=960000 hash=2516d0fe4c09ba26 wav=...
```

几个数字可能对不上、但**不影响验收**的地方：`bitrate` 来自 `codecpar->bit_rate`，FLAC/OGG 经常是 0；`pts` 末尾会差几十毫秒（编码器尾部 padding）；`duration` 是容器报的，可能和实际解码长度差几个样本。

**真正的硬指标是三个 `hash` 和 `bytes`**：

| 样本 | bytes | hash |
| --- | --- | --- |
| test.m4a (AAC 44.1k 2ch) | 882000 | `9e253440599a9111` |
| test.flac (FLAC 48k 2ch) | 960000 | `ade4c9dff2b87f33` |
| test.opus (Opus 48k 2ch) | 960000 | `2516d0fe4c09ba26` |

## M1 验收判据（四条全绿才算过）

1. `[init] libentry.so loaded` 出现 → NAPI 模块加载成功，`.so` 的依赖链在设备上通了
2. 每个样本都有 `[open] format=... codec=... rate=... ch=...` 且数值合理 → 解封装 OK
3. 每个样本都有 `[read] packets>0 ... eof=1` → 能读完整条流
4. 三行 `[decode] hash=` 与上表一致 → 解码 + 重采样 + 写 WAV 全链路一致
5. 全程没有 `[error]` 行

hash 若差一点点（比如末尾几个样本 padding 差异），把 WAV 捞出来逐样本比：

```bash
python test/compare.py --wav test.m4a=out.m4a.wav
```

## 怎么跑

```bash
# 1. 构建（在本机 MSYS2 里，或者直接在 DevEco 里点 Run）
bash build/hvigor-build.sh
#    产物：harmony/entry/build/default/outputs/default/entry-default-unsigned.hap

# 2. 签名安装：DevEco 打开 harmony/ → Project Structure → Signing Configs →
#    勾选自动生成签名（需登录华为账号）→ Run
```

装好后点应用里那个按钮，然后抓日志：

```bash
hdc shell "hilog -T FFM1"          # 只看我们这条 tag
hdc hilog | findstr FFM1           # Windows 本机侧
```

> ⚠️ **签过名之后必看**：DevEco 会把本机证书的绝对路径（带用户名）和加密后的密码写进 `harmony/build-profile.json5`。提交前清回 `"signingConfigs": []`；仓库自带的 `.githooks/pre-commit` 会拦这件事，启用方式 `git config core.hooksPath .githooks`。

## 已知限制（M1 故意不做的）

- **mp3 解不了**：软解白名单是 aac/alac/ape/ac3/dca/flac/opus/wmav2，没有 mp3。测 mp3 会看到 `[error] avcodec_open2 ...`，这是预期行为，mp3 归 M3 的平台解码。
- **同步阻塞**：NAPI 在当前线程解，5 秒音频几十毫秒，先不挪线程；M2 接播放必须挪。
- **只有整文件解**：没有流式 read / seek。`readPackets` 读完文件就在 EOF，不还原位置。
- **只有 rawfile 拷出来的路径**：`Index.ets` 把 rawfile 写到 `filesDir` 再传给 native。
